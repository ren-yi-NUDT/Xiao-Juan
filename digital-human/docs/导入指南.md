# 四类资产导入指南（人设 / 声音 / 形象 / 知识库）

前提：服务已启动，浏览器打开 <http://localhost:5173>。
下面同时给出 **WebUI 操作** 和 **接口/文件路径**，两种方式等价，任选其一。

---

## 1. 形象（Avatar）

### 关键机制

上传不是"凭空生成一个形象"，而是 **复制一个 base avatar 的动作骨架与构图，再用你的图片或视频替换素材**。
所以：

- base avatar 决定**动作、姿态、镜头构图**——想要讲解时有手势，就选本身带手势的视频类 base；
- 你上传的图片/视频只决定**长相、服装、背景**；
- 同一 base 换素材后，动作逻辑与 base 完全一致。

### WebUI 操作

形象库 → 「从本地上传新形象」→ 选基础 Avatar → 填名称 → **图片或视频二选一**（不能同时传）→
可选「上传时抠除背景」→ 等待处理。

### 接口

```
POST /avatars/custom      (multipart)
  base_avatar_id    必填，必须已存在于资产目录且含 manifest.json
  name              必填，重复名会自动加后缀
  image | video     二选一，传两个直接 400
  model             可选，覆盖 manifest 里的 model_type
  person_mode       可选 single / multi
  remove_background 可选，开启需配 rembg 与 u2net.onnx
```

### 素材要求

| 项目 | 图片 | 视频 |
| --- | --- | --- |
| 上限 | 10 MB | 走 `_read_upload_video` 校验，建议 ≤30 s、≤20 MB |
| 内容 | 正脸/近正脸、无遮挡、光照均匀、背景干净 | 人脸全程清晰、头部动作不要过大、帧率稳定 |
| 常见失败 | 人脸检测不到、美颜过重、侧脸 | 压缩伪影重、人脸中途丢失 |

### 脚本方式（批量、可复现）

```bash
cd ~/opentalking-workspace/opentalking

# 图片形象
uv run python scripts/prepare_wav2lip_image_asset.py \
  --source-image /path/to/guide.png \
  --out ./examples/avatars/guide-female \
  --avatar-id guide-female --name "讲解员小景"

# 视频形象（带手势的讲解视频，抽帧生成动作）
uv run python scripts/prepare_wav2lip_video_asset.py \
  --source-video /path/to/guide.mp4 \
  --out ./examples/avatars/guide-female \
  --avatar-id guide-female --name "讲解员小景" \
  --max-frames 125
```

- 输出目录必须在 `OPENTALKING_AVATARS_DIR`（当前 `./examples/avatars`）下；
- 生成后**重启服务**或刷新页面才可见；
- 目录结构：`manifest.json` / `preview.png` / `reference.png` / `frames/` / `source/`。

### 预热（换形象后第一次会慢）

```
POST /avatars/{avatar_id}/prewarm
```

## 2. 声音（Voice / TTS）

### A. 直接用系统音色（零成本）

WebUI「语音与 TTS」→ 选 provider `edge` → 选音色。配置里默认 `zh-CN-XiaoxiaoNeural`。
常用中文女声：`zh-CN-XiaoxiaoNeural`、`zh-CN-XiaoyiNeural`、`zh-CN-XiaohanNeural`、`zh-CN-XiaomengNeural`。

### B. 音色克隆（你自己的讲解员音色）

WebUI「语音与 TTS」→ 上传音色样本 → 选 provider → 填标签与样本文案。

```
POST /voices/clone      (multipart)
  provider       local_cosyvoice | local_f5_tts | indextts | cosyvoice | dashscope | xiaomi_mimo
  target_model   与 provider 匹配的模型名
  display_label  音色显示名
  audio          参考音频（≤12 MB，服务端统一转 24 kHz 单声道 wav）
  prompt_text    参考音频里说的原文（零样本克隆要求与音频严格一致）
  prefix / preferred_name  可选
```

provider 选择建议：

| provider | 是否需要本机权重/Key | 说明 |
| --- | --- | --- |
| `dashscope` | 需 DashScope Key | 千问音色复刻，走 base64，不需要公网回调，最省事 |
| `xiaomi_mimo` | 需小米 Key | 合成时把参考音频作为 data URI 传给 `mimo-v2.5-tts-voiceclone` |
| `local_cosyvoice` | 需本地 CosyVoice 权重 + 独立 sidecar venv | 全本地，显存占用另算（8 GB 卡要谨慎） |
| `indextts` / `local_f5_tts` | 需 sidecar 服务 | 效果更好，部署更重 |

录音要求：安静环境、单人、10–30 秒、语速平稳、不要有背景音乐，最好是一段你讲解词里的真实句子。

音色列表与删除：`GET /voices`、`DELETE /voices/{id}`。

## 3. 人设（Persona）

### 包格式

- 后缀 **`.otpersona`** 或 **`.zip`**，≤200 MB；
- 解包后至少包含 `persona.json`，提示词可以放 `prompts/` 下再做引用。

参考仓库自带示例：`~/opentalking-workspace/opentalking/examples/personas/customer-support-zh/`

```json
{
  "schema_version": "1.0",
  "id": "scenic-guide-zh",
  "name": "景区讲解员",
  "locale": "zh-CN",
  "avatar": { "id": "woman", "model": "wav2lip" },
  "voice":  { "provider": "edge", "voice_id": "zh-CN-XiaoxiaoNeural" },
  "agent":  {
    "system_prompt": "prompts/system.md",
    "style_prompt": "prompts/style.md",
    "memory_enabled": true,
    "knowledge_enabled": true
  },
  "runtime": { "stt_provider": "sensevoice", "tts_provider": "edge", "preferred_backend": "local" },
  "safety": { "authorized_avatar": true, "authorized_voice": true, "content_label_required": true }
}
```

### 导入

```
POST /personas/validate   先校验，不会落库
POST /personas/import     正式导入
GET  /personas            列表
GET  /personas/{id}/export 导出
```

WebUI 侧在「角色」页面导入同一个包；导入后可在界面里直接编辑 `persona-md`（等价 `PUT /personas/{id}/persona-md`）。

## 4. 知识库（LightRAG）

### 路径

```
POST   /agent/knowledge-bases                    建库
POST   /agent/knowledge-bases/{kb_id}/documents  上传单个文档（multipart, file）
POST   /agent/knowledge-bases/{kb_id}/documents/import  从已有文档批量导入
GET    /agent/knowledge-bases/{kb_id}            库状态（indexed / available / reason）
POST   /agent/knowledge-bases/{kb_id}/lightrag/query    直接试检索（limit ≤20）
PUT    /agent/avatars/{avatar_id}/knowledge-bases       把知识库绑定到某个形象
```

WebUI 侧：「资产库 / 知识材料」建库 → 上传 → 等索引完成 → 会话里勾选。

### 落盘位置

`OPENTALKING_AGENT_KNOWLEDGE_ROOT`（当前 `./data/knowledge`，相对仓库根）。
也可以把文件直接拷进去再在界面里刷新索引。

### 检索链路依赖

- 索引与查询走 LightRAG，`OPENTALKING_AGENT_LIGHTRAG_QUERY_MODE=hybrid`；
- embedding：`text-embedding-v4`、1024 维，**需要 DashScope 类的 Key**（`config/env.scenic` 里已引用 LLM 的 Key）；
- 不配 embedding，库能建但检索会返回 `available=false` 之类的 reason，讲解时等于没知识库。

### 讲解场景的资料组织建议

- 一景点一文件，文件名带序号（`02-01-迎客松.md`），方便按需勾选；
- 每篇开头一段 2–3 行的"结论摘要"，检索命中后模型更容易用；
- 票价/开放时间这类易变信息，写上"以现场公示为准"，避免数字过期后被照读；
- 不要整本 PDF 直接塞进去，噪声大、召回差。

## 汇总：四类资产的存放位置

| 资产 | 存放位置 | 生效方式 |
| --- | --- | --- |
| 形象 | `~/opentalking-workspace/opentalking/examples/avatars/<id>/` | 重启服务 / 刷新 WebUI |
| 声音（克隆） | 音色条目写入 `data/opentalking.sqlite3`，参考音频存服务端数据目录 | 立即可用 |
| 人设 | persona 存储（`/personas/import` 写入） | 立即可用 |
| 知识库 | `opentalking/data/knowledge/` + LightRAG 索引 | 索引完成后可用 |
