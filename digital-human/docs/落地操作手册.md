## 零、先说结论：你的 skill 不能原样接入

我核对了 OpenTalking 的 LLM 通路，它发出去的东西长这样：

```python
payload = {"model": self.model, "messages": messages, "stream": True}
```

整个代码库里**没有** `tools` / `tool_calls` / `function_call` 任何一处实现（grep 结果为空）。
也就是说它只会做一件事：把「系统提示词 + 最近若干轮对话 + 知识库检索片段」发给一个 OpenAI 兼容的 chat 接口，把返回的文字念出来。

所以你的 skill 要拆成两半：

| skill 的组成 | 能不能搬过来 | 搬到哪 |
| --- | --- | --- |
| 角色设定、语气、讲解规则（prompt 部分） | ✅ 100% 能 | 人设包 `prompts/system.md` + `style.md` |
| 领域知识、话术库、案例（资料部分） | ✅ 能 | 人设包 `knowledge/` 或独立知识库 |
| 工具调用、读文件、跑脚本、多步流程 | ❌ 不能 | 系统不支持 tool calling |
| 记忆以外的状态管理 | ⚠️ 有限 | 只有 `memory_enabled` 的对话摘要 |

**唯一能"整包直接接"的路径**：让 ds harness 对外暴露一个 OpenAI 兼容的 `/v1/chat/completions` 接口（skill 在 harness 内部跑完，只吐最终文本）。这样 OpenTalking 只当"耳朵+嘴+脸"，大脑还是你的 harness。走这条路就见第 7 节。

## 一、填 LLM Key（已完成）

### 拿 Key

1. 打开 <https://bailian.console.aliyun.com/>，支付宝/淘宝账号登录
2. 完成**个人实名认证**（不做不给 Key）

4. 右上角头像 → **API-KEY** → 创建我的 API-KEY → 复制 `sk-...`（只显示一次）
5. 新用户有免费 token 额度，优先用 `qwen-flash-character` + `qwen3.7-text-embedding-flash`（见「当前状态」）

### 填进去

编辑 `$P\config\env.scenic` 第 39 行：

```bash
OPENTALKING_LLM_API_KEY=sk-你的key
```

> ⚠️ **不要只填 WebUI 的「API配置」页**。那个页面写入的是仓库里的 `.env`，而启动脚本会把 `env.scenic` 的变量 `set -a` 全量导出成环境变量（包括空值 `OPENTALKING_LLM_API_KEY=""`），环境变量优先级高于 `.env`，重启后会被空值盖掉。**以 `env.scenic` 为准。**

### 先单独验证 Key 有效

```powershell
wsl -d Ubuntu -- bash -lc 'curl -s https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer sk-你的key" -d "{\"model\":\"qwen-flash-character\",\"messages\":[{\"role\":\"user\",\"content\":\"说一句你好\"}]}"'
```

能看到 `choices` 就说明 Key 和网络都没问题。报 `Arrearage` / `insufficient_quota` 是额度用完，去控制台充值即可。

### 可选：换模型

这个 Key 是个多模型网关，`/compatible-mode/v1/models` 能看到 qwen / deepseek / kimi / GLM / MiniMax 等一大批。
数字人场景要的是**首句延迟低**，因为你说话时 LLM 边吐字、TTS 边合成、画面边渲染，模型一慢整段就卡。所以优先选 flash 档：

| 模型 | 说明 |
| --- | --- |
| `qwen-flash-character` | **当前默认**。角色扮演模型，人设还原更好；本账户欠费状态下实测可用，有免费额度 |
| `qwen-flash-character-2026-02-26` | 快照版，也可用；但免费额度已下架，不建议 |

改法：只改 `OPENTALKING_LLM_MODEL=` 一行，重启生效。

### 2.5 ffmpeg（仅"绕过 launcher 自己跑脚本"时才需要）

先说清事实，避免误导：**正常启动服务时 ffmpeg 是没问题的**。
`scripts/quickstart/start_opentalking.sh:161` 会执行
`export OPENTALKING_FFMPEG_BIN="$(quickstart_resolve_ffmpeg)"`，
而 `quickstart_resolve_ffmpeg()` 的回退链是：环境变量 → PATH 里的 `ffmpeg` → `imageio_ffmpeg.get_ffmpeg_exe()`。
实测运行中的进程里 `OPENTALKING_FFMPEG_BIN` 已经是
`.venv/.../imageio_ffmpeg/binaries/ffmpeg-linux-x86_64-v9.0.2`。

**但**：`providers/stt/dashscope/adapter.py::_ffmpeg_bin()` 本身是

```python
return os.environ.get("OPENTALKING_FFMPEG_BIN", "ffmpeg").strip() or "ffmpeg"
```

它只读环境变量、**不回退 imageio**。所以如果你绕过 launcher 直接调适配器（写脚本、跑单测、用 CLI），
就会抛 `FileNotFoundError: [Errno 2] No such file or directory: 'ffmpeg'`。

为了让这类场景也能跑，已经做了一层保险（可反复执行）：

```powershell
wsl -d Ubuntu -- bash "/mnt/d/项目/xiao_juan/Xiao-Juan/digital-human/scripts/11_fix_ffmpeg.sh"
```

它把 venv 内 imageio-ffmpeg 的静态全功能二进制（含 x264 / mp3lame / opus）`chmod +x` 后
软链到 `~/.local/bin/ffmpeg`，而启动脚本本来就把 `~/.local/bin` 放在 PATH 最前面。
有 sudo 的话 `sudo apt install -y ffmpeg` 效果一样。

## 七、自己设定形象和声音

两种东西的机制不一样，分开说。

### 7.1 形象（换"人"）

#### 方式 A：上传一张图片（最快，1 分钟）

WebUI：会话页 → 形象选择区 → **自定义形象** → 填名字 + 选图片。

它背后是 `POST /avatars/custom`，表单字段：

| 字段 | 说明 |
| --- | --- |
| `base_avatar_id` | **必填**，拿哪个自带形象当模板（一般填 `woman`），会复制它的目录再替换素材 |
| `name` | 显示名，也是目录名来源 |
| `model` | 填 `wav2lip`（真实渲染） |
| `person_mode` | `single`（单人） |
| `remove_background` | `true` 会走抠图，得到透明背景；纯色背景素材建议开 |
| `image` / `video` | **二选一**，不能都给 |

限制（源码 `apps/api/routes/avatars.py`）：

- 图片 ≤ 10 MB；长边会被压到 `OPENTALKING_CUSTOM_AVATAR_MAX_WIDTH/HEIGHT`，默认 **720×1280**
- 视频 ≤ 200 MB，只认 `.mp4/.webm/.mov/.avi`
- 8 GB 显存下，Wav2Lip 实际处理再压到 ≤640×800 更稳

图片要求（决定像不像真人）：

- 正面、平视、**嘴部无遮挡**（别戴口罩/手挡下巴/侧脸超过 15°）
- 肩部以上半身，头部占画面 1/4 ~ 1/2
- 背景干净、光线均匀，避免强烈逆光和重阴影
- 不要用卡通/严重美颜/多人合照

命令行等价写法：

```powershell
wsl -d Ubuntu -- bash -lc 'curl -s -X POST http://127.0.0.1:8210/avatars/custom -F "base_avatar_id=woman" -F "name=讲解员小景" -F "model=wav2lip" -F "remove_background=true" -F "image=@/mnt/d/项目/xiao_juan/Xiao-Juan/digital-human/assets/guide.png"'
```

#### 方式 B：录制视频（口型更自然，要预处理）

项目自带预处理脚本 `scripts/prepare_wav2lip_video_asset.py`，它做四件事：抽帧、给每帧检测嘴部关键点、算人脸裁剪框、写 `manifest.json`。

```powershell
wsl -d Ubuntu -- bash -lc 'cd ~/opentalking-workspace/opentalking && set -a && source "/mnt/d/项目/xiao_juan/Xiao-Juan/digital-human/config/env.scenic" && set +a && .venv/bin/python scripts/prepare_wav2lip_video_asset.py --source-video /mnt/d/项目/xiao_juan/Xiao-Juan/digital-human/assets/guide.mp4 --out ./examples/avatars/guide-female --avatar-id guide-female --name "讲解员小景" --target-width 640 --target-height 800 --fps 25 --max-frames 125'
```

**关于时长，之前手册写的"20–40 秒"是错的**：`--max-frames` 默认 125，脚本**只取前 125 帧**
（25 fps ≈ 5 秒）就停，后面的直接丢掉。所以：

- 素材拍 **6–10 秒**即可，够循环
- 想保留更长就调大 `--max-frames`，但帧缓存会线性变大，预热更慢、更吃显存
- 素材要求：固定机位、正脸、头部动作小、可带轻微手势、无音乐、不要走来走去、不要遮挡嘴
- 尺寸：8 GB 卡用 `--target-width 640 --target-height 800`

生成后**重启服务**才会出现在形象列表里。

#### 换完必须预热

```powershell
wsl -d Ubuntu -- bash -lc 'curl -s -X POST http://127.0.0.1:8210/avatars/你的形象id/prewarm -H "Content-Type: application/json" -d "{\"model\":\"wav2lip\"}"'
```

返回 `"status":"ready"` 且 `cache.frames` 大于 0 才算成功。首次约 5–8 秒，显存会涨 3–4 GB。

### 7.2 声音（换"嗓子"）

#### 方式 A：切 Edge 音色（免费、免 Key，改一行）

`config/env.scenic:65`：

```bash
OPENTALKING_TTS_EDGE_VOICE=zh-CN-XiaoyiNeural
```

内置推荐的 6 个中文音色：

| voice_id | 感觉 |
| --- | --- |
| `zh-CN-XiaoxiaoNeural` | 女声，温和自然（当前默认） |
| `zh-CN-XiaoyiNeural` | 女声，更年轻活泼 |
| `zh-CN-XiaohanNeural` | 女声，温柔，适合讲文化 |
| `zh-CN-XiaomengNeural` | 女声，偏甜、活泼 |
| `zh-CN-YunxiNeural` | 男声，年轻 |
| `zh-CN-YunjianNeural` / `zh-CN-YunyangNeural` | 男声，播音/新闻感 |

代码只做**格式校验**（`^[a-z]{2,3}-[A-Za-z]{2,4}-[A-Za-z0-9]+Neural$`），不限于这 6 个——
Edge 的任意合法 ShortName 都能用（含 `zh-HK-*`、`en-US-*`、`*-MultilingualNeural`）。
改完重启生效；想先试听就直接打：

```powershell
wsl -d Ubuntu -- bash -lc 'curl -s -X POST http://127.0.0.1:8210/tts/preview -H "Content-Type: application/json" -d "{\"text\":\"欢迎来到灵山胜境\",\"tts_provider\":\"edge\",\"voice\":\"zh-CN-XiaoyiNeural\"}" -o /tmp/t.wav && ls -l /tmp/t.wav'
```

#### 方式 B：克隆你自己的声音（要账户正常 + 10~30 秒录音）

WebUI 有「声音复刻」面板（`apps/web/src/components/BailianVoiceClone.tsx`），等价接口：

```powershell
wsl -d Ubuntu -- bash -lc 'curl -s -X POST http://127.0.0.1:8210/voices/clone -F "provider=dashscope" -F "target_model=qwen3-tts-vc-realtime-2026-01-15" -F "display_label=讲解员本音" -F "preferred_name=guide01" -F "audio=@/mnt/d/项目/xiao_juan/Xiao-Juan/digital-human/assets/voice_sample.wav"'
```

参数含义：

| 字段 | 说明 |
| --- | --- |
| `provider` | `dashscope`（千问复刻）/ `local_cosyvoice` / `indextts` / `cosyvoice` / `xiaomi_mimo` |
| `target_model` | 复刻和合成都必须用**同一个模型**；千问填 `qwen3-tts-vc-realtime-2026-01-15` |
| `display_label` | 你在列表里看到的名字 |
| `preferred_name` | 千问专用，小写字母开头，只含 `a-z0-9_`，≤20 字符 |
| `audio` | 录音文件，< 12 MB；服务端自动转 24 kHz 单声道 WAV |
| `prompt_text` | 仅本地 CosyVoice/IndexTTS 需要：**录音对应的文字**，必须一字不差 |

录音要求（这几点直接决定像不像你）：

- 单人、安静房间、无背景音乐/回声/键盘声
- 普通话、语速平稳、情绪中性，**10–30 秒**
- 内容覆盖多一点音节（别只念"你好"），建议照读一段 30 字左右的讲解词
- 别用电话录音、别用带 BGM 的短视频音轨

返回里的 `voice_id` 就是你要填的东西。然后把 env 改成：

```bash
OPENTALKING_TTS_DEFAULT_PROVIDER=dashscope
OPENTALKING_TTS_DASHSCOPE_MODEL=qwen3-tts-vc-realtime-2026-01-15
OPENTALKING_TTS_DASHSCOPE_VOICE=返回的voice_id
OPENTALKING_TTS_DASHSCOPE_API_KEY=$OPENTALKING_LLM_API_KEY
```

> 注意：复刻模型（`*-vc-*`）和实时合成模型（`qwen3-tts-flash-realtime`）**不是同一条链路**，
> 混用会合成失败或退回默认音色。

本地复刻（`local_cosyvoice` / `indextts`）不需要联网，但要先下模型，而且会吃显存——
8 GB 卡上和 Wav2Lip 同时跑会很紧张，建议错峰或换 12 GB 以上的卡。

#### 方式 C：把声音写进人设包（这样换机器也跟着走）

`persona/scenic-guide-zh/persona.json`：

```json
"voice": {
  "provider": "dashscope",
  "voice_id": "你那串复刻返回的 voice_id",
  "model": "qwen3-tts-vc-realtime-2026-01-15"
},
"runtime": {
  "tts_provider": "dashscope"
}
```

**有个坑**：源码 `persona/session.py:43` 是
`tts_provider = runtime.tts_provider or voice.provider` —— **`runtime.tts_provider` 优先级更高**。
你现在模板里写的是 `"tts_provider": "edge"`，如果只改 `voice.provider` 不改这里，
导入后人设仍然会用 edge 音色。两个地方要一起改，或者干脆删掉 `runtime.tts_provider`。

同理，克隆音色要把 `safety.authorized_voice` 设为 `true`（表示你已获得该声音授权）。

## 八、如果走"harness 整包转发"路线

你的 skill 在 ds harness 里跑，只要那个 harness 能对外提供 OpenAI 兼容的 chat 接口，改这四行就能接：

```bash
OPENTALKING_LLM_PROVIDER=openai_compatible
OPENTALKING_LLM_BASE_URL=http://你的harness地址/v1
OPENTALKING_LLM_API_KEY=harness的key（没有就随便填一个非空值）
OPENTALKING_LLM_MODEL=harness侧的模型或应用ID
```

注意三点：

1. 必须是 `POST {base_url}/chat/completions`，请求体带 `model` / `messages` / `stream:true`，返回 SSE 流。
2. `messages` 是纯 `{role, content}` 字符串数组，**不会有 tools 字段**，harness 侧得自己决定怎么处理。
3. 知识库的 embedding **不能跟着换**（harness 一般不出 embedding 接口）。把 `OPENTALKING_AGENT_LIGHTRAG_EMBEDDING_*` 继续指向百炼 `text-embedding-v4` 或硅基流动 `bge-m3`，否则检索永久 `available=false`。

## 十、排错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 对话/检索报 `Arrearage` / `overdue-payment` | Key 所属账户欠费或额度用尽（chat 也会中招） | 去 <https://bailian.console.aliyun.com/> 实名/充值；恢复后跑 `scripts/31_reindex_lingshan.sh` |
| 索引报 `batch size is invalid, should not be larger than 10` | LightRAG 默认 16 条一批，DashScope embedding 上限 10 | 保留 `OPENTALKING_KNOWLEDGE_EMBEDDING_BATCH_SIZE=8`，重启，重建索引 |
| 知识库 `indexed=false reason=index_failed` | 看 `kv_store_doc_status.json` 里的 `error_msg` | 逐条错误定位：欠费 / 批量 / 模型名，不要只看前端状态 |
| 对话报 `LLM 未配置` | Key 没生效 | `curl /health` 看 `llm_key_set`；确认改的是 `env.scenic` 不是 `.env`；重启 |
| 回答完全不提知识点 | 知识库 `available=false` | Key 未配 / 索引没跑完 / 没勾选。先跑第 5 节的 `lightrag/query` 自测 |
| `personas/import` 返回 400 `persona missing field: description` | 文档示例缺 `description` | 补上非空 `description` |
| 导入报 `persona.json` 找不到 | 压缩包多套了一层目录 | 进到 `scenic-guide-zh` 目录里再 `Compress-Archive -Path *` |
| 语音没反应 | STT provider 还是 sensevoice 但模型没下 | 切 `dashscope`，或下模型（第 2 节） |
| 说话报 `FileNotFoundError: 'ffmpeg'` | 绕过 launcher 直接调适配器，且 `OPENTALKING_FFMPEG_BIN` 未设 | 跑 `scripts/11_fix_ffmpeg.sh`（第 2.5 节）。正常启动服务时不会出现 |
| 说话报 CUDA out of memory | 832 长边 + batch 4 在 8 GB 卡上偏满（预热后已占 5.45 GB） | `OPENTALKING_WAV2LIP_MAX_LONG_EDGE=640`、`BATCH_SIZE=4`，重启 |
| 浏览器不弹麦克风授权 | 用了非 localhost 地址 | 用 `http://localhost:5173` |
| 画面卡顿 / 显存爆 | 分辨率太高 | `OPENTALKING_WAV2LIP_MAX_LONG_EDGE=640`、`BATCH_SIZE=4`、素材 ≤640×800 |
| 换形象后列表里没有 | 资产目录不在 `OPENTALKING_AVATARS_DIR` 下 | 放回 `examples/avatars/` 并重启 |
